# 구미 뉴스 모니터링

네이버·다음에 올라오는 기사를 키워드별로 10분마다 모아서 보여주는 사이트입니다.
링크만 있으면 누구나 PC·휴대폰에서 볼 수 있고, 서버나 사무실 PC를 켜둘 필요가 없습니다.

```
GitHub Actions (10분마다 자동 실행)
  └ collect.py : 네이버 API + 다음 검색 → 중복 정리·묶기·논조 판정 → data/news.json 저장
                 새 기사가 있으면 텔레그램/이메일 알림
GitHub Pages
  └ index.html : data/news.json 을 읽어서 화면에 표시 (5분마다 자동 새로고침)
```

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 사이트 화면 |
| `collect.py` | 기사 수집기 |
| `config.json` | 키워드, 제외어, 논조 단어, 보관 기간 설정 |
| `.github/workflows/collect.yml` | 10분마다 수집기를 돌리는 예약 작업 |
| `requirements.txt` | 수집기에 필요한 파이썬 라이브러리 |
| `.nojekyll` | GitHub Pages 가 파일을 그대로 올리도록 하는 표시 (지우지 마세요) |

## 처음 설정 (약 20분, 한 번만)

### 1. 네이버 검색 API 키 발급
1. https://developers.naver.com 로그인 → 상단 **Application → 애플리케이션 등록**
2. 애플리케이션 이름: 아무거나 (예: 구미뉴스모니터링)
3. 사용 API: **검색** 선택
4. 비로그인 오픈 API 서비스 환경: **WEB 설정**, 웹 서비스 URL 에 `https://github.com` 입력
5. 등록 후 나오는 **Client ID**, **Client Secret** 을 메모

> 기존 구미데일리 뉴스 모니터링 시스템에서 쓰던 키를 그대로 써도 됩니다. 하루 25,000회까지 무료이고, 이 사이트는 하루 약 430회만 씁니다.

### 2. GitHub 저장소 만들기
1. https://github.com 가입/로그인 → 오른쪽 위 **+ → New repository**
2. Repository name: 예) `gumi-news` / **Public** 선택 → Create repository
3. **uploading an existing file** 링크를 눌러 이 폴더 안의 파일을 전부 끌어다 놓기
   - `.github` 폴더와 `.nojekyll` 은 숨김 파일이라 안 보일 수 있습니다. 압축을 푼 폴더에서 숨김 파일 보기를 켠 뒤 함께 올려 주세요.
   - 업로드 후 저장소에 `.github/workflows/collect.yml` 이 보이면 정상입니다.

### 3. 비밀값 등록 (API 키는 여기에만, 화면이나 파일에는 절대 노출되지 않음)
저장소 **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 값 | 필수 |
|---|---|---|
| `NAVER_CLIENT_ID` | 네이버 Client ID | 필수 |
| `NAVER_CLIENT_SECRET` | 네이버 Client Secret | 필수 |
| `TELEGRAM_BOT_TOKEN` | 텔레그램 봇 토큰 (아래 5번) | 알림 쓸 때 |
| `TELEGRAM_CHAT_ID` | 알림 받을 채팅 ID, 여러 개면 쉼표로 | 알림 쓸 때 |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `MAIL_TO` | 이메일 알림 (아래 6번) | 선택 |

같은 화면의 **Variables** 탭에서 `SITE_URL` 에 사이트 주소(4번에서 확인)를 넣으면 알림 끝에 "전체 보기" 링크가 붙습니다.

### 4. 사이트 공개 + 자동 수집 켜기
1. **Settings → Actions → General** 맨 아래 *Workflow permissions* → **Read and write permissions** 선택 → Save
2. **Settings → Pages** → Source: *Deploy from a branch* → Branch: **main**, 폴더 **/(root)** → Save
3. **Actions** 탭 → 왼쪽 **뉴스 수집** → **Run workflow** 버튼으로 첫 수집 실행 (1분 정도)
4. 1~2분 뒤 `https://<GitHub아이디>.github.io/gumi-news/` 접속 → 이 주소를 직원들에게 공유

이후로는 10분마다 알아서 수집됩니다. 첫 수집 때는 기존 기사가 한꺼번에 들어오므로 알림을 보내지 않습니다.

### 5. 텔레그램 알림 (선택, 추천)
1. 텔레그램에서 **@BotFather** 검색 → `/newbot` → 봇 이름 입력 → **토큰** 발급
2. 만든 봇에게 아무 말이나 보내기 (단체방이면 봇을 방에 초대 후 아무 말이나)
3. 브라우저에서 `https://api.telegram.org/bot<토큰>/getUpdates` 열기 → `"chat":{"id": 숫자` 의 숫자가 채팅 ID (단체방은 `-` 로 시작)
4. 3번 표에 두 값 등록

### 6. 이메일 알림 (선택)
Gmail 기준: `SMTP_HOST`=smtp.gmail.com, `SMTP_PORT`=465, `SMTP_USER`=보내는 주소, `SMTP_PASS`=Google 계정의 **앱 비밀번호**(일반 비밀번호 아님), `MAIL_TO`=받는 주소(쉼표로 여러 명).
기관 메일 서버를 쓰려면 전산 담당자에게 SMTP 주소와 포트를 확인하세요.

## 키워드 추가·수정

저장소에서 `config.json` → 연필 아이콘 → 수정 → **Commit changes**. 저장하면 바로 한 번 수집되고, 사이트에 탭이 자동으로 생깁니다.

```json
{
  "name": "금오산",              // 탭에 보일 이름
  "query": "금오산",             // 검색어. 여러 개면 ["금오산", "금오산도립공원"]
  "exclude": ["금오산 등반대회 참가 모집"],  // 이 말이 들어간 기사는 제외
  "alert": false                 // true 면 새 기사 알림
}
```

- 위 예시의 `// 설명`은 이해를 돕기 위한 것이라 실제 파일에는 넣으면 안 됩니다.
- 키워드 사이에 쉼표 `,` 를 빠뜨리면 수집이 멈춥니다. 수정 후 Actions 탭에서 초록 체크가 뜨는지 확인하세요.
- `구미` 는 "구미가 당긴다" 같은 표현이 섞여서 제외어를 넣어 두었습니다. 엉뚱한 기사가 보이면 `exclude` 에 추가하세요.
- 키워드를 지우면 그 키워드로만 모인 기사도 다음 수집 때 함께 정리됩니다.

### 그 밖의 설정

| 항목 | 기본값 | 설명 |
|---|---|---|
| `retention_days` | 30 | 며칠 치 기사를 보관할지 |
| `alert_only_new_stories` | true | 이미 알린 보도를 다른 매체가 받아 쓴 경우 알림 생략 |
| `cluster_threshold` | 0.55 | 제목이 얼마나 비슷해야 "같은 보도"로 묶을지 (높을수록 엄격) |
| `sentiment` | | 긍정/부정 판정 단어 목록. 업무에 맞게 더하거나 빼세요 |
| `press_map` | {} | 도메인을 언론사 이름으로 바꿔 표시. 예) `{"gumiilbo.com": "구미일보"}` |
| `daum_enabled` | true | 다음 수집 끄기/켜기 |

## 화면 기능

- **키워드 탭**: 전체 / 키워드별. 숫자는 선택한 기간의 기사 수, 노란 숫자는 새 기사 수
- **새 기사 표시**: 마지막으로 창을 닫은 뒤 들어온 기사에 노란 줄. "모두 읽음"으로 지우기
- **같은 보도 묶기**: 한 보도자료를 여러 매체가 받아 쓴 기사를 하나로 묶고 "같은 보도 N건 더 보기"로 펼침
- **논조**: 제목·요약의 단어로 긍정/중립/부정을 자동 표시. 부정 기사는 제목이 빨간색. 단어 기반이라 참고용입니다
- **필터**: 기간, 포털(네이버/다음), 논조, 언론사, 검색어
- **보도 통계**: 최근 14일 건수(빨간 부분은 부정 기사), 논조 비율, 많이 보도한 언론사, 수집 상태
- **보고용 복사**: 지금 목록을 번호 매긴 보고 문안으로 복사 (기사 하나만 복사도 가능)
- **엑셀 저장**: 지금 목록을 CSV 로 저장 (엑셀에서 한글 깨짐 없이 열림)
- **브라우저 알림**: 🔔 을 켜두면 창이 열려 있는 동안 새 기사 알림
- 5분마다 자동 새로고침, 다크 모드, 휴대폰 화면 지원

## 알아둘 점

- **"실시간"은 10분 간격**입니다. GitHub 예약 작업은 사용량이 몰리면 5~15분 늦어질 수 있습니다.
- **다음은 공식 뉴스 API가 없어** 검색 결과 페이지를 읽어 옵니다. 다음이 화면 구조를 바꾸면 수집이 멈출 수 있고, 그때는 사이트 왼쪽 "수집 상태"에 빨간 글씨로 표시됩니다. 네이버 수집은 영향 없이 계속됩니다. 다음 기사의 시각은 "3시간 전" 같은 표시로 계산해서 "무렵"이 붙습니다.
- **공개 범위**: 무료 GitHub Pages 는 저장소와 사이트가 공개됩니다. 모이는 내용은 이미 공개된 기사 제목·링크뿐이고 API 키는 Secrets 에만 있어 노출되지 않지만, 주소를 아는 사람은 누구나 볼 수 있습니다.
- **기관 내부망**에서 `github.io` 접속이 막혀 있을 수 있습니다. 공유 전에 사무실 PC에서 한 번 열어 보세요.
- 공개 저장소는 60일 동안 아무 활동이 없으면 예약 작업이 멈출 수 있습니다. 수집 커밋이 계속 쌓이므로 보통은 문제없지만, 멈추면 Actions 탭에서 다시 켜면 됩니다.
- 수집이 40분 넘게 멈추면 사이트 상단에 빨간 안내가 뜹니다. Actions 탭의 실패 기록(빨간 X)을 눌러 오류를 확인하세요.
